=========================================================================
Date 2026-10-15.  Tree: branch testing-gcc32, HEAD 8f87f8a.  Companion of port/ps2_gs_audit.txt (U2, U3, U8).

METHOD
------
Static only; nothing was run, nothing in src/, port/ or the build was changed.
- Section 1: src/vu1/prog*.vsm (read against docs/systems/vu1/*.md), src/sys/vu1_packet.c, the callers
  (src/sys/gfxm_d_c.c, gfxm_e.c, gfxm_e_b.c, src/battle/stgm_a.c), port/src/gs/gs_vu1.c; the GIF tags and A+D
  data the programs only copy were read from the game files with the section 2 scanner.
- Section 2: python scanner (scratchpad offline/bt3walk.py, vif.py, scan_assets.py) over every file of
  gamedata/pzs3us0 and pzs3us1 (3400 files). A file is taken apart as port/tools/dc_tex.c does (texture table,
  font, BPE part, offset table of parts, or a format of its own). In every non-texture part each 16-byte aligned
  quadword that is a DMA tag (id cnt/next/ref/call/ret/end/refe) whose upper 64 bits are two valid VIF codes is
  followed as a DMA source chain (TTE: the tag's upper half is VIF data, as Vu1Pkt_* build theirs), the VIF
  stream decoded (UNPACK sizes with STCYCL, MPG, DIRECT, STROW/STCOL/STMASK), and every MSCAL/MSCNT batch's
  UNPACK V4-32 at TOPS+0 decoded as the program reads it (GIF tags, A+D register + value). Chains that do not
  decode are counted as rejects. Every texture table entry's pixel and CLUT packet is decoded (VIF DIRECT, GIF
  tags, A+D registers). gamedata/pzs3us2 (65201 files) is all ADX audio (first bytes 80 00, as dc_tex's
  catalogue port/build/dc/assets/disc.xml also says) and gamedata/disc/DATA holds the PSS/ADX movies only.
- Section 3: python port of gs_pvr.c pkt_key / KEY_SHAPE / KEY_DIRECT (tex_check.py) over every texture entry and
  palette of every file, looked up in the index of port/build/dc/assets/tex.pak (read only); source read for
  every upload path (Port_TexNative / Port_PalNative / Port_ClutTint callers) and every run-time texture.

1. VU1 PROGRAMS: WHAT EACH ONE SENDS TO THE GS (resolves U3)
=============================================================
Common to all: input is V4-32 floats only (no fixed-point input formats anywhere: section 2 found only UNPACK
V4-32). Matrices are 4 column quadwords, p' = x*c0 + y*c1 + z*c2 + c3. Output per vertex, always 3 quadwords
in register order ST(Q) / RGBAQ / XYZF2 as named by the strip's GIF tag (PRE=1, NREG 3, REGS 0x412):
  ST   = (s, t, 1) * q with q = 1/w (perspective STQ; Q is written by the ST register's third word)
  RGBA = ftoi0 of float colour (0..255 range, 0x80 = 1.0)
  XYZF = ftoi4 of screen x, y (12.4, XYOFFSET space), z ftoi4 too, fourth word ftoi4(1.0)=16 (fog 0) or with
         bit 15 set (ADC: vertex kicks no triangle).  Z is 24-bit (ZBUF PSMZ24).
No program writes PRIM by A+D, no program sends other registers than its batch's A+D quadwords (TEX0_1/TEX0_2 or
the dummy PRIM=0 of stage batches). PRIM comes from the strip/fan GIF tag. Every program is a pure function of
(constants, batch) -> GIF packet: no read-back, no state across batches except the clipper's fan tag (prog4/6).
Addresses: prog0 0x2BF6B0 (127 instr), 1 0x2BFAB0 (124), 2a 0x2BFEA0 (99), 2b 0x2C01C0 (101), 4 0x2C04F0 (399),
5 0x2C1180 (429), 6 0x2C1F00 (451), 7 0x2C2D30 (104), 8 0x2C3080 (94).

PER PROGRAM: caller -> GS context / PRIM / XGKICKs / clipping / textures (tags confirmed from game data, sec. 2)
prog0  fighter part, lit (BtlObjDraw_DrawModel -> ObjDraw_DrawParts mode 0, Vu1Pkt_CallProg0; chain = model
       file part +0x60).  Consts 0x22 qw: mtxA, mtxB, ofsA, ofsB, light (Mtx_MakeNormalLight), screen, clip,
       color (view->color), k=(128,128,128,128).  Batch: +0 A+D tag (NLOOP1, no EOP), +1 TEX0_1, +2 TEX0_2,
       +3 strip tag layer 0 (PRIM 0x5C TRISTRIP IIP TME ABE ctx1), +4 strip tag layer 1 (PRIM 0x25C = same in
       ctx2, EOP), vertices 3 qw: pos xyz w=weight A, normal, (s,t,1).
       Skin: p = B(p-ofsB) + (A(p-ofsA) - B(p-ofsB)) * w.  ONE xgkick per batch:
         tag+0, TEX0_1, tag+3, n x (STQ=(s,t,1)q, RGBA=int(color), XYZF)        layer 0, context 1
         tag+0, TEX0_2, tag+4, n x (STQ=(u,0,1)q, RGBA=128x4, XYZF)              layer 1, context 2
         u = 0.5 + 0.5 * dot(-L, n_skinned) (blended A/B by w): a 1D toon ramp lookup.
       n <= 38.  No clipping: a vertex whose triangle (it + 2 before) leaves the clip volume gets ADC.
       TEX0_1 = model texture (T4/T8, TFX modulate, TCC 1), TEX0_2 = ramp (T8 256x.., TFX decal, TCC 1, at
       TBP 0x3D40 after MdlTex_RebaseChain).  Env: BtlObjDraw_SetEnv, ObjGs_AddTexEnv (ALPHA_1 0x64 fix 0x80,
       TEST 0x50000, TEX1 0x60, CLAMP_2 5), ObjGs_AddFrame1/Frame2Alpha (ALPHA_2 0x..62 / 0x..48), ZBUF both.
prog1  fade pass (BtlObjDraw_DrawModelFade, parts with flag 1; same chain).  Same frame as prog0, single matrix;
       layer 1 TEX0_2 from const 26 (the fade texture, not the batch's), u,v = 0.5+0.5*(light*n).xy.  A batch
       whose first normal.w low 16 bits are 0 kicks only an empty tag (0x8000).  Env ObjGs_AddFadeEnv (ctx1 FBMSK
       0xFFFFFF = alpha only, ALPHA_1 0x44; ctx2 ALPHA 0x58, CLAMP_2 5) + ObjGs_AddFadeTex (TEST_1 alpha ref,
       TEX0_2, TEXFLUSH).
prog2a flat shadow (ObjShadow_BeginFlat, ObjDraw_DrawPartsFlat mode 2, CallProg2 part+0x60).  Consts: bones /
       pivots 0-9, colour 10 (light colour, a=128), S 11-14, C 15-18 (screen/clip times the plane projection).
       Uses batch +0, +1, +4 and the vertices; ONE xgkick: tag+0, TEX0_1, tag+4, n x (ST, flat RGBA, XYZF).
       ADC on triangles outside.  PRMODECONT=0 / PRMODE 0x48 (gouraud + ABE, no TME, ctx1) set before, so of the
       tag's PRIM (0x25C) only the type (strip) counts: drawn untextured, blended, through context 1.
       ZBUF no write, TEST 0x54000, FBA_1 1, ALPHA_1 0x64 fix 0x46.  The TEX0_1 A+D still goes out (harmless).
prog2b silhouette into the shadow page (ObjShadow_BeginRender -> ObjShadow_LoadProg: FRAME_1 0x150 (TBP 0x2A00)
       PSMCT32 256x256, SCISSOR 0..255, XYOFFSET 0x7800, PRMODE 0x48, RGBAQ 0x80808080; page cleared by 8 sprites).
       As 2a without ADC (whole model, colour 128).
prog4  stage geometry, groups 0-5 (StgModel_Draw; LoadProg4 consts screen, clip, clip->screen; BASE 0x8D).
       1st MSCNT of the chain = object header (1 qw at VU 0x1E): the fan tag 0x00008005_302EC000 (PRIM 0x5D
       TRIFAN IIP TME ABE ctx1, PRE, ST RGBAQ XYZF2).  Batch: +0 A+D tag (NLOOP 1, EOP), +1 A+D data all zero
       (writes PRIM=0: a no-op, NOT a texture), +2 strip tag (PRIM 0x5C ctx1, EOP), vertices pos (w=1.0),
       colour floats (a=128.0), (s,t,1,0).  XGKICKs: +0..+1, then the strip; triangles crossing the clip volume
       get ADC and are re-sent as fans (Sutherland-Hodgman, 6 planes, triangle grown x1.005 about its centroid),
       one empty-tag kick + one fan kick each.  Texture: StgModel_SetTexture (TexFile_UploadOne to 0x2A00 /
       CLUT 0x32C0, Dma_AddTex0(tex0 | 0x0006580400002A00)).  Env: StgModel_SetDrawEnv (FRAME, ZBUF 0x310000E0,
       ALPHA_1 0x44, TEST_1 0x5001B / 0x507FB / 0x54000+ZMSK, TEX1 0x60, CLAMP 0, COLCLAMP 1).
prog5  no caller (LoadProg5/CallProg5 unreferenced): dead.
prog6  ground shadow (ObjShadow_Draw; input built by ObjShadow_BuildPacket in C, not an asset).  Consts world->
       screen, world->clip, clip->screen, world->shadow cam, scale.  Batch +0/+1 TEX0_1 (never sent), +2 strip tag
       PRIM 0x5C, vertex 4 qw (pos, w = no-draw flag; normal unused; colour; st slot).  s,t = (c.xy*scale+1)/2
       from the shadow camera.  Clipping as prog4 (fan tag PRIM 0x5D).  Texture = the shadow page 0x2A00
       (ObjGs_AddShadowTexEnv: PSMCT24 256x256, CLAMP 5, TEX1 0, TEST 0x5400F, ALPHA 0x44 fix 0x80, TEXA, ZBUF
       no write).
prog7  stage debris, group 6 (StgModel_DrawDebris).  Consts L (VU0), S, C, 12.w alpha.  Stage batch layout;
       pos.w low 16 bits != 0 -> ADC; colour alpha replaced by the mesh alpha.  ONE kick (+0,+1,+2 then
       vertices).  No clipping.  TEST_1 0x51809 (StgModel_SetTestDebris).
prog8  animated stage objects (StgModel_DrawAnims -> Vu1Node_Draw -> CallProg8(node), chain node->vif).
       = prog2a with the stage batch layout: consts A = node world, B = parent, pivots, S, C; two-matrix skin by
       pos.w.  Header 3 qw: +1 TEX0 patched by Vu1Node_OrFlags (TBP 0x3480 / CBP 0x3700<<5, TexFile_UploadPacked).
       Per-vertex colour (floats).  ONE kick.  No clipping (ADC when outside).  <= 81 vertices per batch.
       Env StgModel_SetAnimDrawEnv (TEST_1 0x507FB).

PORT TODAY: port/src/gs/gs_vu1.c interprets the microcode or runs HLE paths (hle_program0/1/2/4/6/78, chosen by
program size) that produce GsGpu_DrawVu0/Vu4/Vu6 triangles directly; the PC renderer clips on the GPU instead of
building fans.  The HLE paths already ARE native renderers fed by VIF data, minus the GS register state.

REPLACEMENT SPEC (for R6: no VU1 emulation on DC)
- Input: walk the asset chain once at load (or each draw) as section 2 did: every batch = header (1/3/5 qw)
  + V4-32 vertices; keep pointers, no VIF decoding at draw time (pre-parse to {hdr, nverts, verts*}).
- Per program: transform (mtx_mul_vec4), skin (lerp), light dot -> ramp u (prog0/1), project, ADC rule ->
  RndPoly records (x, y, z 24-bit, s, t, q, rgba) with the context of the tag (ctx1 layer, ctx2 layer), the
  texture from the batch's TEX0 (model: TBP/CBP after MdlTex_RebaseChain -> Port_TexHandle; ramp 0x3D40; stage:
  the texture StgModel_SetTexture bound; prog6: the shadow render target).  Prog4/6 fans become ordinary
  clipped triangles (the PVR clips against near only; x/y can go to the TA unclipped within limits).
- State per program is fixed (listed above) and already followed by Rnd_GsFollow from the env packets.
- Strips: n <= 38 (prog0), stage strips NLOOP up to 63 (seen), split into RndPoly triangles or PVR strips.

==================================
Scope: 3400 files (pzs3us0 + pzs3us1), 383956 leaf parts scanned, 17269 texture tables.
Chains decoded: 140442; batches (MSCNT/MSCAL runs) 810075.  All GS geometry lives in three families:

                               incl. 2722 in "mouth set A", 33 in
                               "BObjMdl.unk84" (extra streams, see OPEN), 5 in
                               "character effect pack" (consumer OPEN)
  stage chain with object hdr  stage file part 1                              61023    61023  1 qw    4 (fan tag)
                                                                                     + 3-qw batches below
  stage chain, plain           stage file part 1 (42709) + part 9 anim (64)   42773
  all 3-qw stage batches                                                              341101  3 qw    4/7/8
Every one of these 139689 chains: DMA tags 'ret' only (one tag, TTE), VIF commands only UNPACK V4-32 (cmd 0x6C,
cl/wl 1/1, TOPS-relative, addr 0 = header, addr = header size = vertices), MSCNT (imm 0) and NOP.  Exact count
check: UNPACK 1557703 = 2 x (407239 + 341101) + 61023.  No DIRECT/DIRECTHL, MPG, MSCAL, STROW/STCOL/STMASK,

register writes other than the header quadwords below, never upload microcode, never use fixed-point formats.
Vertices: 3 qw each in every batch (nqw % 3 == 0 for all 748340 vertex unpacks).

   +2 tag  NLOOP=n EOP=1 PRE=1 PRIM 0x05C TRISTRIP IIP TME ABE CTXT1 REGS ST,RGBAQ,XYZF2;  n = 3..81.

 No batch in any family carries ALPHA/TEST/FRAME/ZBUF/CLAMP/TEX1/FOG or any PRIM with FGE (fog) or FST (UV).
 All alpha/test/z state comes from the C env packets listed in section 1.  Fog never comes from assets.

Texture upload packets in assets (89786 = 47076 pixel + 42706 CLUT + 4 font): every one is VIF DIRECT + GIF
PACKED A+D with exactly TRXPOS, TRXREG, TRXDIR, then IMAGE (BITBLTBUF is supplied by the game: Tex_Upload*,
ObjDraw_UploadTextures, EftVram_Upload, HudRes_UploadTex, FlashDraw_UploadTex).  No other register appears.

Outliers (all checked, all false positives of the byte scan, none is GS data):
- dc_tex disc.xml gs_uploads="1" on 4 pmdl parts (pzs3us1/02113, 02114, 02117, 02118, part 3 +0x42A70): an
  index table that happens to contain 0x50 ... 0x53 words; not an upload.
- 753 chain candidates that do not decode or decode to 1-2 commands with address tags (refe 717, next 6,
  ref 6, bad tag 17, runs off 2, nohdr 712) and 1023 "DIRECT data runs off": all in non-GS parts (sound bank
  header 323, SPU ADPCM 162, motion 92, AI 67, attack records 40, menu layout 10, stage data 2) or inside texel
  data of stage texture tables (57).  MPG 16 / MSCAL 524 / STROW 8 / DIRECTHL 2 occur only in these.
- pzs3us2: 65201 ADX files, no GS data.  disc/DATA: movies only (MovieTag_* builds its packets in C).
- cmdl (EftBurst_RelocateModel, stage change model): s16 vertices/triangles, no GS/VIF data (drawn in C).

Conclusion for the native port: every asset GS/VIF stream can be converted offline (dc_tex-like tool) or parsed
at load into {header TEX0s, strip vertex arrays}; the only run-time patches are MdlTex_RebaseChain (TBP/CBP of
5-qw +1/+2) and Vu1Node_OrFlags (3-qw +1), both of which become texture-handle lookups.

3. TEXTURE PACK COVERAGE (U8)
=============================
tex.pak (port/build/dc/assets/tex.pak, 25959 entries) against every texture table entry of every file, keyed as
port/src/gs/gs_pvr.c does (pkt_key FNV over the IMAGE data, KEY_SHAPE(TEX0), ^KEY_DIRECT for CT32/24/16,
palettes by raw key; shape checks as nat_get / Port_PalNative):
  entries found            psm         lookup                 hit        unique keys
  42496 indexed            T4 15819,   key                    42496      11761
                           T8 26677
   4582 direct             CT32        key ^ KEY_DIRECT       4582        876
  42708 palettes           CT32        raw key                42708      11571
  (font 5tnF: 2 textures + 2 palettes, included above)
  MISS 0, shape mismatch 0, unkeyable packet 0, PSM not handled by nat_get (T8H/T4HL/T4HH/CT16S...) 0.
  Pack entries accounted for: 24208 hit by the lookups above + 876 KEY_T8 views of the direct ones + 875 256-colour
  palettes made from direct CT32 16x16 entries (dc_tex pal_emit of an entry's pixels) = 25959 = all.
So: every texture and palette AS STORED IN THE FILES is in the pack, by the key the runtime computes.

What the pack cannot cover (run-time content; listed by uploader):
- ** Fighter material palettes rewritten before upload (NEW FINDING) **: BtlObjMdl_InitAlphaSlots
  (src/sys/gfxm_e_b.c:124) sets the alpha byte of the first 16 CLUT colours (packet + 0x60 + j*4 + 3) of every
  material texture [texFirst, texFirst+texCount) except texNoAlpha to slot + alphaRow*15, alphaRow claimed at
  bind (BtlObjVis_AllocFreeBit, 0..14).  ObjDraw_UploadTextures then calls Port_PalNative on the rewritten
  packet, whose FNV key no longer matches.  Simulated over all 742 pmdl files: 9187 material entries, 79
  texNoAlpha; of the 9108 rewritten palettes 8427 miss the pack for every row 0..14 and 681 hit for exactly one
  row (when slot + row*15 == 0x80, the file's value).  => practically every fighter palette falls back to the
  GS upload (Dma_AddRef) today, and Port_ClutTint / GsPvr_Pal find no native palette at those CBPs.
  The pixels (Port_TexNative) are unaffected.  Fix options (not applied): key palettes with the first 16
  alpha bytes masked (dc_tex + pkt_key for this caller), or look up by the key computed before the rewrite
  (cache it on bind) and then patch the 16 alphas into the native palette copy.  The slot alpha is the per-
  object alpha table index (BtlObj_FillAlphaRow / BtlObj_UploadAlphaTable): the DC renderer must reproduce what
  the GS does with it (OPEN: which pass reads those alphas, see audit M2/M4).
- Generated on the GS (render targets, never in files): shadow page FBP 0x150 / TBP 0x2A00 (prog2b ->
  prog6), frame copies (ScrWarp, StgPanBlur_CopyScreen, StgBlur, StgFog, StgHaze, GfxLens_PutCapture,
  GfxPost_DrawGlow, GfxWater_DrawView), Z-as-texture passes (audit M2), ScrXfade_StoreHalf readback,
  EftSurf_BeginDraw other colour buffer.
- Generated in RAM by C: GfxClut_InitPacket LUTs (12 callers), the gfxm_a.c CLUTs built per frame (stage
  glare / fog / depth tint, clut[k+3] = gStgGlare.alpha etc.), ObjDraw_AddClutPass (replaced by Port_ClutTint),
  movie frames (Movie_Run), the light/ramp page 0x3D40 (in pack as KEY_T8 view of its CT32 source: covered).
- Effect / HUD / Flash uploads (EftVram_Upload: EftVramImage has TexEntry's layout at 0x08/0x0C/0x18/0x1C/
  0x38/0x3C; HudRes_UploadTex; FlashDraw_UploadTex; mouth/face entries BtlObj_GetFaceTexture): their data are
  texture-table entries of the files, all covered above, as long as the game does not modify them before
  upload (no writer found besides InitAlphaSlots; source grep of clut/pix writes: only gfxm_a.c generated
  CLUTs and InitAlphaSlots).
