METHOD
------
1. Symbol graphs: nm/objdump -dr over every object of each build; function -> referenced symbol edges,
   including relocations in data (vtables / class tables) so address-taken calls are edges too.
     graph_pc: 9999 nodes, 62316 edges, 15601 symbols.   graph_dc: 7417 nodes, 37063 edges, 11743 symbols.
2. Boundary layer L1 (the emulation's entry points as the game sees them):
     src/sys/dma.c (sys_dma.o), src/sys/gfx_ot.c (sys_gfx_ot.o), src/sys/vu1_packet.c (sys_vu1_packet.o),
     every symbol defined in port/src/gs/*.o (gs_core, gs_vu1, gs_draw, gs_pvr, gs_sony), pc_gs_marker.o
     (records / Rnd_*), pc_plat_gs.o (gHwEe/gHwGs/Port_DmaChcr), pc_plat_stub.o sceGs*, pc_plat_movie.o
     sceMpeg*, the variables gDma* / gOt*, and the VU1 microcode (vu1_micro.data.o D_002BF6B0..D_002C3080).
3. Direct referrers: every game function with an edge into L1.  PC 295 = 210 producers (build or describe
   GS data) + 85 drivers (flush / reset / sync / timers / IOP).  DC 293 (difference: Timer_GetFrames,
   Timer_GetMicros reference gHwEe only on PC).
4. Closure: 1403 nodes upstream of producers (1264 functions + 139 data tables, mostly gEft*Class vtables);
   503 game functions downstream of L1 users, 429 of them not upstream (helpers called by producers).
5. Pointer-parameter packet writers (functions that never name L1 but write GIF data into a buffer they are
   handed) found by a downscan of producer callees + an allscan of GIF-tag/register stores:
   GfxLens_PutCapture, FlashDraw_PutSprite, ObjShadow_BuildPacket, EftBurst_PutModelEnv, MovieTag_BuildBlocks,
   GfxClut_InitPacket, MdlTex_RebaseChain, TexChain_WriteTags (unreachable).  Inlined helpers (0 graph
   callers, called in source) resolved by source grep.  Backstop: a constant scan (GIF tag / A+D / BITBLTBUF
   patterns) over src/ found nothing outside these sets (0x20000000 hits are unrelated flags).
6. Each producer body was read and classified.  Address-taken producers: EftBlade_Draw (gEftBladeClass),
   EftFlash_Draw (gEftFlashClass) only.

STATUS KEYS
-----------
RECORD       draws through a renderer record (Port_Quad/Port_Poly/Rnd_Fill/Rnd_Sprite/Rnd_Draw) on PORT;
             a GS-packet fallback still exists in the same function.
DECODED      writes an OT GS packet that Rnd_OtTake (port/src/rnd_gs.c) decodes into Port_Poly at Ot_Send
             when state allows; otherwise copied into the DL and drawn by gs_core.
PACKET       GS packet drawn only by the gs_core emulation.
STATE        register writes only (A+D env, scissor, markers, sync, display regs); followed into gRndCtx by
             Rnd_GsFollow and/or mirrored by Rnd_Set* calls.
UPLOAD-BOTH  native texture/palette handle (Port_TexNative/PalNative) with a GS IMAGE upload fallback.
UPLOAD       GS IMAGE upload only.
READBACK     reads GS memory back (Gs_StoreImage).
VU1          VIF1 chain run by the gs_vu1 microprogram emulation.
ASSET        the GS/VIF data comes from game files (cannot be enumerated statically).
UNRESOLVED   cannot be proven from the build outputs / source (listed below).
Combined statuses (DECODED+STATE, VU1+ASSET) mean both apply.

Transport ("how" column):  DL = display list (Dma_BeginDirect/EndDirect/AddData/Add*) -> Dma_Flush ->
Port_DmaChcr(1) -> gs_core Port_GsVif1Chain;  OT = gOtCur/gOtZ/gOtLast packet -> Ot_Draw -> Ot_Send ->
Rnd_OtTake/DL;  REC = record Gs_RecordPush (drawn by gs_core run_chain at its DL address);  RS = Rnd_Set*
renderer state;  MK = Port_GsMarker / 0x7B..0x7F pseudo-registers in the DL;  UPL = upload helpers
(Port_TexNative or BITBLTBUF + REF);  VU1 = Vu1Pkt_* VIF1 chain;  SONY = sceGs* (gs_sony.c / plat_stub);
GIF2 = GIF channel 2 via gHwEe D2_CHCR;  HW = gHwGs/gHwEe registers;  pvr/core/hook = direct calls into
gs_pvr / gs_core / gs_draw.

4. GS MEMORY DEPENDENCIES (what reads or aliases sVram contents, beyond "draw into the frame")
==============================================================================================
Frame/Z layout used by the game: FBP 0 / 0x70 (TBP 0 / 0xE00) colour buffers, ZBP 0xE0 (TBP 0x1C00) PSMZ24,
work pages FBP 0x150 (TBP 0x2A00), 0x16C (0x2D80), 0x170, 0x1F6/0x1F8; texture area 0x2A00..0x3FFF
(0x2D00 burst, 0x3000 Flash, 0x32C0/0x2A00 stage, 0x3480/0x3700 stage anims, 0x3D40 seam ramp).
  M1 Frame -> texture copies: ScrWarp, StgPanBlur_CopyScreen, StgBlur, StgFog, StgHaze, GfxLens_PutCapture,
     GfxPost_DrawGlow, GfxWater_DrawView.
  M2 Z buffer read as texture (PSMT8H/PSMCT through CLUT): GfxPost_DrawDepthClut(At), StgFog, StgHaze,
     StgGlare, StgDepthTint, StgPanBlur, GfxAlphaKey, GfxDepthFog (+ GfxPost_ShiftHighWord,
     GfxPost_CopyAlphaToDepth aliasing alpha <-> Z high byte).
  M3 Destination alpha as stencil (DATE/DATM, FBA, FBMSK alpha-only): HUD masks, FlashDraw_MaskQuad,
     EftBurst_ClearAlphaPlane, HudGfx_ClearAlpha, HudSprite_DrawAlpha*, ObjGlow, ObjOutline, GfxDepthFog.
     Mirrored for records by Rnd_SetMark/SetTest/SetWrite.
  M4 Render into a palette: ObjDraw_AddClutPass fallback (FRAME = cbp>>5).  Port_ClutTint replaces it.
  M5 Render into an off-screen page then sample it: ObjShadow_AddTargetEnv + ObjShadow_Draw (0x150 / 0x2A00),
     EftSurf_BeginDraw (FRAME_2 = the other colour buffer).
  M6 Readback: ScrXfade_StoreHalf (Gs_StoreImage) + ScrXfade_Draw re-upload.
  M7 Uploads: all UPLOAD-BOTH / UPLOAD producers; the GS fallback writes sVram, which gs_draw/gs_pvr then
     hash (Gs_VramRead, Gs_PageHash, clut_hash) to find textures that were not native.
  M8 Gs_SrcFreed (Heap_Free) keeps gs_core's map from GS pages to RAM sources consistent.
